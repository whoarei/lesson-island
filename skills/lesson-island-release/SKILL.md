# 课文岛版本发布

适用于当前 Lesson Island 仓库，包名为 `top.mossmoss.lessonisland`。先读取仓库说明、Git 状态和现有构建脚本；不要将本技能应用到其他 Android 项目。

## 发布版本号是必需输入

- 应用版本采用纯数字 `x.y.z`，每段为非负整数且不带多余前导零，例如 `0.1.2`、`1.0.0`。Git 标签使用 `v` 前缀，例如 `v0.1.2`。
- 版本号只来自用户对**本次发布**的明确指示或确认。当前 `versionName`、上一个标签、变更规模和历史发布消息都不能代替用户选择。
- **用户未说明本次发布版本号时，必须先询问：**“这次课文岛要发布哪个版本？请提供 x.y.z 版本号，例如 0.1.2。”等待明确回复后再继续。可以先做只读检查；不得自行递增、沿用当前版本、把建议当成确认，或因等待超时继续发布。
- 确认之前不修改版本，不构建发布产物，不创建发布提交或标签，不覆盖已有交付文件。收到不符合格式的版本号时，先请用户明确一个符合 `x.y.z` 的版本。
- 用户已经明确给出本次版本时直接执行，不重复询问。只创建或修改本技能、仅提交代码或仅做只读检查，不等于发起一次发布。

## 项目约定

- `app/build.gradle` 的 `versionName` 和 `versionCode` 是版本来源；应用关于页从安装包读取版本。版本变化时提升 `versionCode`；若工作区已为同一个待发布版本完成提升，核查后沿用，避免每次重试重复提升。
- 本机签名配置为 `.local/signing.properties`，默认 keystore 为 `E:/Android/libb.keystore`。Debug、测试包和 Release 使用同一用户证书。凭据缺失时请用户填写私有文件，不生成临时证书或退回其他证书。
- 示例素材只能位于 `app/src/androidTest/assets/fixtures`。正式 APK 不得包含示例课文、图片或音频；首次安装从空课程开始。测试允许临时装载示例，结束时恢复原状态。
- `.local/`、`llm info.txt`、keystore、签名密码和本机配置不进入 Git 或源码包。只分发空白 `signing.properties.example`。

## 执行发布

1. 核对目标版本、已有标签及工作区变更，保留无关改动。更新 `versionName`、必要的 `versionCode`、`CHANGELOG.md`、README 中的当前 APK 路径及交付说明。不要改写历史发布记录来伪造验证结果。
2. 运行 `tools/build.ps1`，产物为 `deliverables/LessonIsland-x.y.z.apk`。脚本会执行构建、JVM 测试和 Lint，并按实际版本命名 APK。
3. 根据改动执行或复用针对当前源码的有效测试。专用模拟器回归使用 `tools/test-android.ps1 -Device <明确的设备序列号>`；目前包含 7 项基础流程，后续以脚本为准。只有需要验证模型链路时才加 `-LiveApi`，它会消耗用户 API 额度。
4. 核对 APK 的包名、版本和签名，证书应与配置的用户 keystore 一致；检查 ZIP 内容，确保没有 `assets/courses`、`assets/audio` 或测试 fixtures。核查首次使用、创建课程入口及本次实际改动。
5. 如用户授权真机安装，先完成所需测试，再用明确的 `adb -s` 设备安装并核对启动与安装版本。沿用会话中已有安装授权，不重复请示；不在真机执行会装载测试课程的仪器测试。签名冲突不自动卸载应用，先保护数据；手机拒绝安装时请用户处理设备端提示后再重试。
6. 检查提交范围、私有文件排除和 `git diff --cached --check`，提交本次发布改动，创建指向实际发布提交的注释标签 `vx.y.z`。现有标签不得强制移动或覆盖；遇到版本重复，先明确是在核验既有发布还是另发新版本。
7. 从该标签使用 `git archive` 生成 `deliverables/LessonIsland-x.y.z-source.zip`，生成 `SHA256SUMS.txt`，确认源码与发布提交一致且不含私有配置。只读核对标签、提交及剩余工作区变更。

默认完成本地 Git 提交、标签、APK、源码包和校验文件。只有用户明确要求推送或远程发布时才操作现有远程仓库；目标缺失时询问目的地，不擅自创建仓库或选择账号。

失败时保留有用日志并处理可恢复问题。缺少用户输入、设备端允许或目标地址时暂停依赖步骤，说明已完成内容与具体缺项；不能把旧 APK 或未完成步骤报告为本次成功发布。

## 完成反馈

简要给出版本、提交、标签、安装包链接和实际验证范围；说明真机是否已经更新。普通提交不能报告为已经发布，模拟器结果不能报告为完整真机测试。
